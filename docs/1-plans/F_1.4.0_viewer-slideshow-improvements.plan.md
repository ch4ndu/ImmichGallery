# Viewer and Slideshow Improvements Implementation Plan

## Overview

Improve playback and navigation in the existing shared media viewer across
Timeline, Album, Person, Search, Favorites, Memories, and nested stacks. Keep
the app read-only against Immich and preserve existing grid-return behavior.
The version in this filename is a planning identifier, not a release/version bump.

## Scope and Owner Decisions

- The owner requested all six slideshow improvements: nonrepeating shuffle with
  history, pause/resume controls, readiness-aware timing and upcoming-slide
  prefetch, remembered settings, independent transitions and motion, and video
  playback policy. Optional date/location/description captions are included.
- Retain photo-viewer items 1, 2, and 5: filmstrip/position, desktop fullscreen,
  and actionable metadata (maps, copy coordinates, show date in Timeline).
- Explicitly exclude photo-viewer items 3, 4, and 6: stack comparison, save/share,
  and Live Photo/Motion Photo playback. No export or motion-photo data work.
- Confirmed: preferences are device-wide; playback position and shuffle history
  live only for the open viewer session. No per-album profiles or restart resume.
- UI testing comes last, after implementation and non-UI verification.
- Finish with local commits; do not push, publish, merge, or release.
- Starting worktree was clean. Work branch: `feat/viewer-slideshow-improvements`.
- Session execution override: owner explicitly selected Astra ultra for ALL
  roles, including implementation and reviews. Use native Astra-ultra agents
  rather than the repository launcher's fixed Sol pins. Do not change the
  repository-wide TRIP installation or defaults for this session preference.

## Problem Statement

Random order currently excludes only the current page and previous chooses a
new random page. Tap stops playback, and Space starts configuration again.
Timers start on page settlement without image readiness. Prefetch follows
adjacent pages even in random mode. Settings reset on each dialog. Videos are
thumbnail-only during slideshows. Normal viewers have no filmstrip and desktop
has no viewer-owned fullscreen control. Location and date metadata are passive.

## Solution Architecture

Architecture approved by the owner on 2026-10-02:

1. Use one shared, viewer-session playback controller for both overlay types.
   Keep pure order/history/timing decisions testable separately from Compose;
   retain pager state, scroll animations, and media rendering in Compose.
   Each nested stack gets an independent controller; covered base sessions pause.
2. Add slideshow preferences to the existing `ServerConfigRepository` settings
   layer through settings UseCases/Actions and a small viewer preferences
   ViewModel. Persist only configuration, never asset IDs or media metadata.
   Preserve these non-sensitive device preferences across logout/session change;
   all session-derived viewer state is still disposed. No Room schema change.
3. Reuse `GetAssetDetailUseCase` for optional captions and info actions. Cache
   successful metadata only within the viewer, deduplicate current-page reads,
   cancel displaced reads, and never bulk-fetch collection metadata.
4. Extend the existing `PlatformVideoPlayer` contract with playback readiness,
   completion/error callbacks, mute, and slideshow-control visibility. Keep
   Chaintech Android/JVM and AVPlayer iOS; do not replace backends.
5. Desktop window host owns fullscreen placement. A composition-scoped bridge
   exposes capability/state/actions to shared viewer UI; mobile has no desktop
   fullscreen control. Restore the entry placement on slideshow/viewer exit.
6. App navigation owns date requests through explicit callbacks and a consumed
   request value. Return to existing Main, select Timeline, then invoke the
   existing date-target workflow after viewer dismissal and Timeline readiness.
   No global navigation singleton and no second Timeline instance.

## Implementation Details

### 1. Playback order, history, timing, and settings

**Existing:** `domain/model/SlideshowConfig.kt`,
`ui/component/StaticPhotoOverlay.kt`,
`ui/screen/timeline/TimelinePhotoOverlay.kt`,
`data/repository/ServerConfigRepository.kt`.

- Replace random-other-page selection with a shuffle cycle and traversable
  history. Previous visits the prior displayed item; Next first replays forward
  history. Only after history ends is a new item selected. Each eligible item
  appears once per cycle, with no immediate repeat across cycle boundaries.
- Sequential remains source-order and wraps. Preserve current asset identity
  when a source changes. Distinguish membership/order identity from readiness
  and materialization identity: Timeline's existing pager projection includes
  `loadedAssetPageIndexes` and is NOT a shuffle-cycle key. Preserve the remaining
  shuffle bag, history cursor, and upcoming target when an unresolved
  `(timeBucket, localOffset)` becomes a known asset without an order change.
  Only actual membership/order changes reconcile or reset a cycle. Preserve
  visited asset identities through candidate resolution and reject stale targets.
- Add Running/Paused/Stopped session state and stable media request identity.
  Pause keeps the remaining dwell time and pan/zoom progress. User-driven page
  changes give the new ready slide a full interval. Resume keeps the session.
- Gate time on current media readiness, uncovered viewer, active application,
  and no blocking detail/options layer. Backgrounding freezes elapsed time;
  reopening Info must not let the show advance behind it.
- Choose the upcoming target before advancing and prefetch its image/bucket.
  Keep requests bounded to current, upcoming, and ordinary nearby viewer needs.
- Give unavailable/loading media a bounded 15-second active wait. On terminal
  error or timeout, show the failure, then skip after a short visible interval.
  Three consecutive failures pause with Retry/Next/Exit, preventing an endless
  blank loop. Success resets the consecutive-failure count. Ignore stale events.
- Extend Timeline's narrow overlay projection with candidate resolution status:
  unresolved/loading, failed, materialized, or unavailable under cache policy.
  Add explicit `onRetryBucket` wiring through `TimelineScreen` to the existing
  eligible retry/materialization path. Ordinary `onBucketNeeded` alone cannot
  retry failed uncached buckets. Under cache-only policy, genuinely absent rows
  require a manual Timeline refresh: show that recovery direction and allow
  exit/skip, rather than restarting an ineffective wait. Never classify failed
  or unavailable candidates as videos when detecting an all-video source.
- Persist order, duration, motion, transition, video policy, mute, video limit,
  captions, and desktop slideshow-fullscreen preference in existing settings.
  Validate duration 1–120 seconds inline; disable Start for invalid input.
  Unknown persisted enum values fall back to supported defaults.
- Preserve initial sequential/5-second/pan-and-zoom behavior, slide transition,
  and thumbnail video policy. New captions and automatic fullscreen default off.

### 2. Shared controls, media readiness, and transitions

**Existing:** `ui/component/SlideshowOptionsDialog.kt`,
`AssetPageContent.kt`, `KenBurnsImage.kt`, `ViewerImagePrefetch.kt`,
`ui/util/DesktopInput.*.kt`, and both overlay owners.

- Add accessible Previous, Pause/Resume, Next, and Exit controls. Tap reveals or
  hides controls; it no longer stops playback. Controls hide after inactivity
  while playing and remain available when paused, focused, or failed.
- Space pauses/resumes an existing show; outside a show it opens options.
  Escape exits slideshow first, then fullscreen, then the viewer on later presses.
  Left/Right follow session history. Exit restores normal viewer chrome.
- Reuse still-image load state where practical; report URL/request-scoped
  success and failure from both still and pan/zoom slideshow render paths.
  A thumbnail placeholder alone does not start the full-resolution dwell timer.
- Motion is Still or Pan-and-zoom; transition is Cut, Fade, or Slide. Cut changes
  pages without animation; Slide uses the pager; Fade crossfades only the old
  and target slide, without visibly traversing intervening shuffled pages.
- No offscreen video playback during transitions. A transition must finish
  before the next dwell starts. Rapid input, pause, and dismissal cancel safely.
- Keep Ken Burns transforms measured and read animation progress in the layer.
  Dwell and motion use the same accumulated active-presentation time, gated by
  readiness and transition completion. Pause/resume retains progress rather
  than resetting the current `isActive` effect; motion begins when the target
  image is ready and cannot finish ahead of its dwell.
- Slideshow wake inhibition is held only while actively presenting playback;
  release on pause/background/exit/disposal and reacquire on active resume.

### 3. Slideshow video policy

**Existing:** `ui/component/PlatformVideoPlayer.kt` plus Android/JVM/iOS actuals,
and `AssetPageContent.kt`.

- Options: Skip videos, Show thumbnail, Play video. Video playback defaults
  muted when selected, with a mute control and an optional positive maximum
  playback duration; blank limit means play to completion.
- Start the active selected video while loading: waiting to call play until a
  playback event arrives would deadlock. Disable looping before playback starts,
  and advance once on completion or the chosen cap. Pausing pauses video. Normal
  viewer playback keeps existing behavior and platform controls.
- Each new slideshow visit gets a fresh media generation and starts from the
  beginning; pause/resume retains the same generation and media position.
  Completion is accepted at most once per generation.
- Android/JVM use observed positive `CurrentTimeChange` progress as the
  conservative readiness predicate available in Chaintech 1.0.53; its JVM event
  resolution is whole seconds. This is progress evidence, not a first-frame
  guarantee. Neither `PauseChange(false)`, known duration, nor initial
  nonbuffering alone establishes readiness. A valid completion before the first
  positive position is accepted once for very short media. Buffering suspends
  active-presentation timing. Use playback position for any chosen video cap.
- iOS uses ready-item status plus observed advancing playback time, with end
  notification as the short-media terminal event. Retain original-first fallback
  within one visit, and do not fail while the existing bounded fallback is still
  making progress. Dispose observers and reject displaced-source callbacks.
- Apply a bounded active-time watchdog both before initial progress and after
  subsequent progress stalls, including videos with no cap. Chaintech's JVM
  listener does not forward every native error through `onError`; never rely
  on that callback alone. Pause/background/covered states freeze the watchdog.
  A fallback source may reset startup observation once; never retry indefinitely.
- Skip resolves lazy Timeline candidates as needed, bounded by one source pass;
  an all-video source pauses with an explanatory message instead of spinning.
  Never eagerly materialize the whole Timeline just to filter videos.
- Missing desktop VLC and denied/unavailable media are explicit playback
  failures subject to the shared bounded policy.

### 4. Filmstrip and position indicator

**Existing:** both overlays, `AssetPageContent.kt`, `StackSessionOverlay.kt`.

- Add position text and a filmstrip toggle to normal viewer chrome. Render
  bounded, lazy thumbnails with selected-item semantics and click-to-page.
  Keep the selection visible as the pager moves. Collapsing leaves position.
- Static sources use their currently materialized ordered list; do not claim
  counts for unloaded server pages or change existing source pagination scope.
- Timeline uses its existing projected total and lazy page resolver. Request
  only visible strip buckets and the selected/upcoming page via `onBucketNeeded`;
  display placeholders until materialized, using the existing cache-only policy.
- Preserve origin return behavior and the existing indicator for Memories;
  avoid competing/doubled progress chrome. Stack sessions remain independently
  navigable and never alter the base viewer/grid return target.
- Hide the strip during slideshow/drag/shared transition; preserve zoom gesture
  priority, letterbox input containment, and bottom safe-area padding.

### 5. Desktop fullscreen

**Existing:** `jvmMain/.../main.kt`, shared/platform desktop input utilities.

- Bind `rememberWindowState` at the desktop host and expose a scoped fullscreen
  controller. Add visible enter/exit action and F shortcut to the viewer.
- Allow slideshow to enter fullscreen via its remembered option. Restore prior
  window placement when exiting that show, closing the owning viewer, or logout.
  A nested viewer must not overwrite its parent's restoration target.
- Distinguish app visibility/minimization from transient focus loss during
  fullscreen changes so presentation does not spuriously stop.

### 6. Metadata actions and captions

**Existing:** `AssetDetailSheet.kt`, `AssetDetail.kt`, `GetAssetDetailUseCase`,
`AppNavigation.kt`, `MainScreen.kt`, source screens, and Timeline date navigation.

- Validate finite latitude/longitude bounds. Open maps only after explicit click
  using a platform URI handler with a safe HTTPS map URL fallback. Copy a plain
  coordinate pair through Compose's supported clipboard API; expose feedback.
- Add Show in Timeline for a valid capture date. Close detail/nested/base viewer
  using existing return callbacks, route to the existing Timeline tab, and
  consume a unique date request through the established cache-based resolver.
  Invalid/missing dates do not expose a broken action; repeated same-date
  requests work. Logout cancels pending requests.
- Optional slideshow captions show the localized capture date plus available
  location/description from a current-slide-only metadata request. Caption
  failure never blocks photo playback. Never show the previous photo's caption
  while awaiting a new response; cap text so controls remain usable.

## Technical Considerations

- **Layering:** settings through repository -> UseCase/Action -> ViewModel;
  metadata through existing detail UseCase. UI owns media/pager presentation.
- **Read-only:** no upload, edit, favorite, delete, server sharing, or export.
- **Cache:** no Room changes. Preferences are lightweight settings; captions,
  history, and playback requests are viewer-lifetime memory. Existing image-cache
  auth/session rotation applies to all new prefetch requests.
- **Concurrency:** keep mutable playback decisions on one owner dispatcher;
  perform potentially large shuffle preparation on Default and network reads on
  IO. Requests capture source/media generation; cancel displaced jobs and
  recheck identity after suspension before state publication.
- **API:** no new endpoint. Use existing authenticated asset detail reads.
  No private media URL may be opened in a browser or copied as a map action.
- **Platform:** all expect/actual signatures compile on Android/iOS/JVM. Video
  end/readiness differs by backend; callbacks must represent observed events.
- **Verification:** no device/simulator execution without explicit owner
  authorization. Desktop UI testing stays at the end. Runtime/platform limits
  must be reported separately from successful compiles and host tests.

## Edge Cases Considered

- Empty/single-item sources; all videos with Skip; first/last wrap; removed or
  reordered assets; source grows mid-show; lazy bucket failures and retry.
- Rapid Next/Previous/toggle input; old image/video callbacks; pause during
  prefetch/loading/transition; background, minimize, fullscreen, and logout.
- Opening Info or a stack over playback; nested fullscreen ownership; Memories
  origin policy; dismissing after a filmstrip jump or failed media.
- Invalid durations/settings/dates/coordinates; missing metadata; huge images;
  long videos; offline state and three consecutive failures.
- Narrow layouts, touch targets, keyboard focus, accessibility labels, caption
  overflow, and reduced/disabled animation preference.

## Performance and Backward Compatibility

No bulk image/metadata preloading, Room migration, new media backend, or API
mutation. A shuffle cycle may need compact index storage proportional to source
size; prepare it off the UI thread. Thumbnails remain bounded 256 x 256 with
existing authenticated cache keys. New settings have explicit defaults.

## Test Impact and Acceptance

- Pure tests: shuffle cycle uniqueness/history/reconciliation; empty/single and
  all-video behavior; pause elapsed time; completion caps; failure bounds and
  stale request rejection. Use deterministic random/time inputs.
- Materializing an unchanged Timeline bucket via upcoming-slide prefetch must
  retain shuffle progress and history. Test recoverable failed bucket Retry and
  missing-cache manual-refresh recovery separately from the all-video condition.
- Video adapter tests reject command-only readiness, accept very short valid
  completion once, ignore stale generations, restart a new visit, preserve
  pause/resume, and catch a no-progress stall after successful startup. Dwell
  and pan/zoom pause/resume must use the same accumulated time.
- Settings tests: round trips, invalid stored values, validation, device-wide
  preferences survive logout while session-derived state does not.
- Integration/helper tests: upcoming prefetch identity, lazy Timeline bucket
  selection, metadata date/coordinate validation, one-shot date request routing,
  fullscreen ownership/restoration and native player callback handling.
- Compile/lint: JVM, Android shared, both iOS ARM64 targets, Android APK, Android
  lint; run affected common tests via JVM and Android host tasks before UI tests.
- UI last: start/configure, pause/resume/Next/Previous, shuffle history, each
  transition/motion/video mode, loading failure/retry, captions, filmstrip
  selection/return, fullscreen restoration, maps/copy/date actions. Exercise
