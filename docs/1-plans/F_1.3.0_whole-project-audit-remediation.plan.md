# Whole-Project Audit Remediation Implementation Plan

## Overview

Version 1.3.0 remediates the actionable findings from the whole-project audit
recorded in `docs/3-code-review/CR_w3_v1.2.0.md`. The work establishes one
application-wide authenticated-session boundary, hardens Immich API and cache
contracts, confines cross-dispatcher runtime state, repairs viewer and
accessibility behavior, and completes the affected Android, iOS, and JVM
Desktop integration paths.

The implementation is deliberately divided into six ordered work items. Each
work item must preserve a compiling, tested repository and end in its own local
commit; no push or release is authorized by this plan. The project remains a
read-only Immich client and Room remains a re-fetchable schema-version-2 cache.

## Planning Decisions And Scope

The user resolved the architecture and product gates as follows:

- The six previously accepted/documented security and release boundaries in
  the audit remain outside this remediation. They will be presented as the
  next-work backlog after this plan is complete.
- Desktop developer-built application images and native packages will include
  a builder-supplied, architecture-matching libVLC runtime. VLC binaries are
  package inputs, not large tracked repository artifacts.
- This is a personal, source-built project with no planned public binary
  releases. The missing project license and the `vlcj` distribution-license
  disposition are explicitly owner-accepted; this plan does not invent a
  license, legal policy, or notice program.
- iOS and JVM video authentication will use Immich's supported `apiKey` query
  parameter through one percent-encoding URL builder. The iOS private
  `AVURLAssetHTTPHeaderFieldsKey` option will be removed.
- Any change to the normalized server URL or API key is a session replacement.
  The old re-fetchable cache is cleared rather than retained or namespaced.
- Automatic redirects are rejected for API and authenticated image clients.
  Users must configure the final Immich server URL; same-origin redirect
  support is not added speculatively.
- Application logging is disabled before platform services or repositories can
  run. Retained log statements and typed errors are still sanitized so a later
  logging-policy change cannot silently restore the audited disclosures.
- Reproducibility work is owner-accepted risk and excluded from implementation:
  no CI workflow, wrapper checksum, dependency verification/locking, SBOM,
  vulnerability scanner, or CI package-structure gate will be added.

## Problem Statement

The current app compiles and its shared host tests pass, but the audited
baseline contains three Critical session-isolation failures, authenticated
redirect and image-cache risks, API compatibility and pagination defects,
cross-dispatcher mutable-state races, viewer identity and lifecycle errors,
accessibility gaps, and incomplete native build/media contracts. Fixing these
independently would leave dangerous ordering gaps: for example, cache clearing
without writer fencing still permits old-session rows to reappear, while
viewer reanchoring without stable page identity can transfer local page state
to a different asset.

The remediation therefore begins with one coherent session mutation protocol,
then repairs data contracts, runtime ownership, UI behavior, and native
integration in dependency order.

## Completion Contract

This plan is complete only when all of the following are true:

1. Every audit ID in the coverage matrix has either a verified remediation or
   the explicit owner-accepted disposition recorded below.
2. Login validation never sends a persisted key to an edited candidate origin,
   normal authenticated clients never forward a key through a redirect, and a
   server/key replacement cannot expose the previous session's Room, Mosaic,
   memory, or Coil state.
3. Logout closes session-write admission, cancels and joins registered old
   work—including Android service-owned manual Timeline work—then clears
   server-scoped state before clearing configuration.
4. API compatibility failures preserve the prior cache; pagination cannot
   repeat, move backward, cycle, or corrupt raw page ordinals.
5. Cross-dispatcher mutable runtime state has one explicit atomic/serialized
   owner and controlled interleaving tests.
6. Every named viewer, detail-grid, scrollbar, choice-row, navigation, and
   slideshow flow is traced through its actual callback/state wiring; compile
   success alone is not accepted as UI verification.
7. Android, iOS, and JVM source/build checks pass in the documented matrix,
   focused tests pass freshly, `git diff --check` passes, and Gradle daemons are
   stopped.
8. Device, simulator, live-server, platform accessibility-service, and packaged
   GUI checks remain explicitly unperformed unless the user separately
   authorizes them during implementation.

## Solution Architecture

### Authenticated session boundary

Add one application-wide session-write fence. A logical cache-producing
operation captures an opaque generation before its first authenticated request,
registers its owning coroutine job, and passes the same token through child
coroutines and edit/Mosaic enrichment. Immediately before each Room or Mosaic
transaction, the repository method that owns that transaction enters the fence
once, validates the generation, and serializes that validation with the write.
Actions register and propagate operations but never wrap repository commit
sections; nested commit entry fails fast instead of attempting to re-enter a
non-reentrant mutex.

A logout or session replacement closes operation admission and advances the
generation before cancellation. It then cancels and joins the registered old
generation, shuts down and rotates the exact Coil singleton, clears Room,
Mosaic, and repository runtime state, and only then clears or replaces settings.
Admission reopens after the mutation finishes. A cleanup failure keeps the old
configuration active and retryable; the advanced generation prevents responses
captured before the failed attempt from committing afterward.

Implementation review added a second stamp component for long-lived runtime
owners. Timeline and detail coordinators capture an owner epoch once and pair it
with the currently admitted generation at each true top-level request. Deferred
children and Android manual-service commands preserve both values. Every
mutation advances the generation; only a successful mutation advances the owner
epoch. This rejects callbacks from an old mounted owner after successful cleanup
but lets the same screen retry after a failed cleanup.

This fence is not held across network requests or CPU layout work. Timeline's
existing bounded bucket concurrency remains intact; only commit validation and
the already-transactional write are serialized with session mutation.

### Network and API boundary

The shared Ktor client becomes credential-neutral and does not follow
redirects. `ImmichApiService` adds a supplied candidate key only to the
candidate authenticated validation request and adds the current key explicitly
to normal configured-origin requests. Candidate ping and public version/ping
requests remain anonymous.

iOS/JVM Coil derive a dedicated authenticated image client configuration that
adds the current key only when the request's scheme, host, and effective port
match the normalized configured origin. Android's image OkHttp interceptor uses
the same exact-origin rule. Both image paths reject redirects.

### Cache and pagination integrity

No Room table changes are required. Album and Person cross-reference rows
already contain `sortOrder`; both full and incremental synchronization will
persist sparse raw response ordinals. DAO range/tail queries will compare exact
raw page windows rather than dropping offsets from a compact filtered list.

One narrow page-token validator receives the current page and consumed set. A
missing token terminates; a valid token must be positive, strictly forward, and
unconsumed. Equal, backward, malformed, and cyclic tokens become typed
compatibility failures without replacing valid cached content.

### Runtime ownership

The plan does not actorize entire ViewModels or introduce a new application
state framework. `PhotoGridLayoutRunner` atomically owns its job/generation pair;
Detail Mosaic invalidation becomes one ordered coordinator transaction; and a
small `TimelineRuntimeStateStore` owns only the collections currently accessed
from multiple dispatchers. Timeline publish/repair producers update keyed
latest-value buffers and signal consumers through conflated wakeups.

### Viewer and UI identity

Viewer opening distinguishes Found, Pending, and Absent selection resolution.
Timeline pager identity uses materialized asset IDs or stable bucket/offset
placeholder IDs, then deliberately reanchors the settled asset across live
projection changes. Timeline scroll capture and restore use one ordered
projection-aware reconciler. Album/Person exit waits for the grid return source
before clearing the overlay selection.

### Platform media and developer packaging

iOS and JVM use one tested query-auth URL builder; iOS retains original-first
playback with current-page-owned fallback but disables PiP until a separate
background-media capability is designed. Android/JVM add a non-consuming tap
observer around native player controls.

Desktop package tasks accept `immichGallery.vlcBundleDir` or
`IMMICH_GALLERY_VLC_BUNDLE_DIR`, validate a complete architecture-matching
libVLC 3 runtime including native core libraries and plugins, copy it into
Compose Desktop application resources, and fail package creation when the
bundle is incomplete. JVM startup points `jna.library.path` at that packaged
resource before Chaintech/vlcj discovery runs. vlcj's built-in
`JnaLibraryPathDirectoryProvider` accepts the exact directory containing
libVLC/libvlccore, and its OS strategy sets the plugin path from the validated
relative layout;
ordinary development run may fall back to an installed VLC, but missing
discovery must show actionable UI.

The repository will not track the large native VLC directory. This makes the
built application image self-contained while keeping source checkout size and
platform-specific binary provenance under the builder's control.

The shared Ktor client installs the persisted key on every request. Saving a
new configuration changes settings without clearing old server/account state.
Logout clears cache without excluding or joining writers. Coil survives logout,
and JVM Settings uses the global Java Preferences root. Production loggers are

**Modifications**:

- Add an opaque `SessionOperationToken` and singleton
  `SessionStateRepository`. The Action/orchestration entry point registers the
  owning `Job` before authenticated I/O and passes the same token to every child.
  Exactly one layer owns each commit fence: the repository method that directly
  owns the Room or Mosaic transaction validates the generation and executes
  that transaction under the mutex excluding session mutation. Actions never
  wrap those repository commit calls.
- Wrap every cache-producing authenticated flow, including edit enrichment and
  Mosaic writes. Do not let nested children capture a fresh token after the
  parent request; the original logical-operation token must be inherited. Mark
  an entered commit in coroutine context and fail fast on nested commit entry so
  a future caller cannot silently deadlock the non-reentrant fence.
- Bind long-lived Timeline/detail runtime work to a session owner epoch as well
  as the generation. Queue, repair, resume, layout, and Android foreground
  commands carry the immutable originating stamp; descendants never recapture a
  newer global value. Successful mutation invalidates the old owner, while
  failed mutation preserves it for retry.
- Implement exclusive mutation ordering: close admission, advance generation,
  snapshot/cancel/join old jobs, rotate/clear Coil, clear Room and both Mosaic
  stores plus runtime cache, then clear or replace configuration, and reopen
  admission. Never hold the fence mutex while joining jobs. Mutation-owned
  cache-clear methods run only after old jobs join and bypass normal commit
  admission; they must not recursively enter the commit fence.
- Replace `SaveServerConfigAction` with suspend
  `ReplaceServerSessionAction`. Exact equality after URL normalization is a
  no-clear fast path; any URL or key change uses the mutation protocol. A clear
  failure leaves the old URL/key in place and surfaces a retryable login error.
- Route `ClearServerConfigAction` through the same mutation protocol. Logout UI
  may show progress but must not rely on disabling the button as its correctness
  boundary.
- Remove the Ktor `defaultRequest` key. Make candidate ping anonymous and send
  the candidate key only to the candidate `/api/albums` validation request.
  Normal authenticated methods attach the current key explicitly.
- Disable automatic redirects in Ktor and in Android's image OkHttp client.
  Build iOS/JVM image clients from a dedicated Ktor configuration that adds the
  key only for exact configured-origin asset requests. Android enforces the
  same scheme/host/effective-port comparison before adding the header.
- Add `ServerScopedImageCache` as the domain-facing cleanup boundary and a
  process-global singleton controller. `App.kt` registers the exact ImageLoader
  produced by the existing singleton factory through that shared controller.
  Mutation shuts down the old loader to cancel requests and clear memory,
  removes its closed disk-cache contents, and prepares a replacement while the
  global slot remains pointed at the shut-down loader. It clears repository

- Align iOS and JVM with Android's process-owned Koin lifetime: start Koin

  pass-through. The controller, configuration repository, and HTTP client then
  share one lifetime, so a recreated host cannot leave the process-global image
  loader reading a disposed root's stale in-memory session.
- Replace the generic temporary `image_cache` directory with platform app-owned

  session cleanup, not secret-bearing names, provides isolation.
- Move `Settings` provisioning from `sharedModule` into platform modules.
  Android/iOS keep their app-owned platform settings backend; JVM uses

  is consequently limited to the app node.
- Before constructing the JVM repository, perform one idempotent migration from

  migrator. For each owned key, preserve an existing app-node destination;

## Type Definitions

The exact names may adjust to local style during implementation, but these
semantic contracts are required:

- `SessionOperationToken`: opaque generation captured once per logical
  cache-producing authenticated operation; contains no raw API key.
- `SessionStateRepository`: registers/unregisters operation jobs, propagates
  tokens to structured children, validates writes, and owns exclusive mutation
  admission/generation.
- `ReplaceServerSessionAction`: compares normalized configuration and performs
  no-op or exclusive replacement; replaces `SaveServerConfigAction`.
- `ServerScopedImageCache`: domain-facing suspend cleanup/rotation boundary.
- `CoilImageCacheController`: owns the exact singleton loader instance/context,
  shutdown, memory/disk cleanup, and replacement installation.
- `PaginationContract`: narrow current/consumed token validation; not a generic
  paging framework.
- `TimelineRuntimeStateStore`: immutable snapshot/CAS owner for audited runtime
  maps, sets, batches, and invalidation.
- `PhotoOverlayResolution`: Found, Pending, or Absent selection state.
- `TimelinePagerPageKey`: stable materialized asset or unresolved bucket-offset
  identity.
- `TimelineScrollAnchorReconciler`: ordered capture/restore state machine keyed
  by projection identity.
- `ViewerImagePrefetch`: bounded neighborhood selection and disposable ownership
  behind a fakeable enqueue boundary.
- `AuthenticatedMediaUrl`: one percent-encoding query-auth builder used by iOS
  and JVM.
- `JvmVlcBootstrap`: packaged-resource/native-discovery preflight and actionable
  availability state.

## Technical Considerations

- **Layering**: repositories own API/Room/session-state access; Actions own
  mutation; ViewModels use Actions/UseCases; Compose forwards intent. The
  domain-facing image-cache interface prevents auth Actions from depending on
  Coil UI implementation.
- **Read-only scope**: all server requests remain reads. This plan adds no
  upload, edit, favorite, delete, share, download-to-user-storage, or server
  administration mutation.
- **Cache ownership**: Room and Mosaic remain re-fetchable version-2 cache;
  decoded image bytes and in-flight Coil work become explicit server-scoped
  cache; Search/Favorites/Memories/detail info remain live-only as documented.
- **No Room migration**: raw sparse ordinals use existing columns and iOS path
  relocation is filesystem-only. Exported schemas must remain unchanged.
- **Async correctness**: cancellation is rethrown; tokens are captured before
  I/O; commit validation is atomic with writes; mutation never joins under its
  mutex; retries are bounded/explicit; queue state is keyed and conflated.
- **Security**: no global credentials, cross-origin header attachment,
  automatic redirect, secret-bearing cache namespace, private logging, or raw
  media URL diagnostic is allowed. Query-auth is the explicit media exception
  accepted by the user and existing architecture.
- **Performance**: session fencing does not cover network/CPU work; caches use
  immutable atomic snapshots; prefetch is viewport bounded; no broad Timeline
  rewrite is authorized. Measurement-only Ken Burns work remains evidence-led.
- **Platform impact**: Android service lifecycle, iOS AVPlayer/storage/Xcode,
  and JVM VLC/sleep paths have separate verification boundaries.
- **Developer packaging**: VLC inclusion is deterministic from an explicit
  local bundle input. Real binaries are not tracked or silently downloaded by
  ordinary builds.
- **Legal posture**: MR-09/m-12 are user-accepted, not technically remediated or
  represented as legal compliance. Reproducibility and security-scanning work
  is also owner-accepted risk and excluded.

## Edge Cases Considered

- Empty, whitespace-only, trailing-slash, same-origin, different-origin, and
  key-only session changes.
- Logout before a request, while a request is suspended, during a Room write,
  during Mosaic work, and after network completion but before commit.
- Mutation cleanup failure, operation cancellation failure/finally cleanup,
  and immediate new login after logout/replacement.
- Candidate URL redirect, configured API redirect, image redirect, origin
  scheme/host/default-port differences, and blank candidate key.
- Empty Timeline columnar result versus missing required columns, optional stack
  absence, mixed image/video, hidden visibility, and future unknown fields.
- Missing, malformed, repeated, backward, cyclic, duplicate-only, and terminal
  page responses; unsupported raw items at page start/middle/tail.
- Concurrent layout launch/cancel, invalidation during newer generation, offer
  during drain, and invalidated checkpoint arriving late.
- Viewer source loading, selected asset removed before open, selected asset
  removed while open, insertion/removal before current page, unresolved bucket,
  first/last/single asset, stack overlay coverage, and rapid dismiss.
- Prefetch of image/video neighbors, viewport changes, rapid swipes, disposal,
  and retry of the same failed original URL.
- Scrollbar progress endpoints/clamping, localized date order, Unknown date,
  label taps, keyboard/switch/accessibility activation, and duplicate Person ID.
- Duplicate refresh/login taps, failure followed by retry, and owner teardown.
- iOS page precomposition, original failure, transcode fallback, inactive-page
  cancellation, and unsupported PiP control.
- Multiple Android service start IDs, overlapping manual/background work,
  notification denial, timeout, destruction, and session cancellation.
- Missing/wrong-architecture/incomplete VLC bundle, spaces in resource paths,

  sleep-inhibitor command.
- Legacy iOS database with WAL/SHM, partial move, preexisting target, backup

## Performance And Cost Impact

- Full cleanup on any URL/key change trades cache retention for deterministic
  isolation and avoids a schema/user-identity migration.
- Serializing only commit validation plus Room transactions should not reduce
  existing network/Mosaic parallelism materially.
- Immutable runtime snapshots allocate small maps/sets on updates but eliminate
  undefined concurrent mutation; keyed conflation bounds backlog by active
  bucket/generation cardinality rather than event count.
- Viewport-bounded prefetch reduces peak decode/network work relative to the
  current original-size unbounded queue.
- Bundled libVLC materially increases developer-built Desktop package size.
  Because the user explicitly selected self-contained playback and no public
  binary release is planned, size is accepted; source checkout remains small.

- Room schema remains version 2 and requires no migration/export change.
- iOS legacy cache files migrate once from Documents to Application Support or
  are discarded safely because they are re-fetchable.
